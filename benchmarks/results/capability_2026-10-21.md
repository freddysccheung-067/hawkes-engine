### The Hessian pass

Gradient evaluations in the Hessian pass: M=2: 40 (P=10, 4.0P), M=4: 144 (P=36, 4.0P), M=6: 312 (P=78, 4.0P), M=8: 544 (P=136, 4.0P). ### Fitted constants

Least squares on the Hessian-mode deltas for N >= 1e5 (seven points, M in 2, 4, 8, N up to 1e7): bytes = 33.0 * N + 3677 * P + 963,698, with P = M + 2M^2 free parameters.

The model follows the data: errors range from -4.9% to +8.6%, the largest at N = 1e5 where the constant term matters. The per-parameter coefficient is poorly determined, since P ranges only from 10 to 136 against N over two decades, so it should not be read as more than "small". The per-event term is the one that matters.

Outcome: **measured, nothing to fix; no code was changed.** Nearly all of a fit is inside the two compiled calls, so Python overhead is not a target. Per event the compiled cost grows as M^2 and flattens to a few ns per cell, which is the cost of one `exp` per cell per event that pair decay needs, since every cell has its own rate and every gap differs. The loop in `cpp/src/workspace.cpp` allocates and copies nothing per event. What remains is a vectorised `exp` or `-march=native`; ADR-006 rules out the second for published wheels and the first is not a cheap, safe change, so it is not made here.

## 6. What the library cannot do at a practical size on this machine

- A single fit with a Hessian at M = 8, N = 1e6 takes 13.8 min (rho 0.3) and 12.3 min (rho 0.85); at M = 6 it takes 4.9 min and 4.9 min. That is a documented cost, not a defect.
- A bootstrap interval at M = 4, N = 1e5, B = 200 takes 8.5 min on one worker and 86.42 s on the default pool. Larger configurations were not timed.
- The Hessian pass costs a fixed 4P gradient evaluations, so its absolute time grows with M (section 1). Its share of the fit falls at M = 8, where the iteration count dominates instead.
- At M >= 6 with about 1e4 events, fits finish but are labelled `marginal` or `unreliable` by the library (section 1). Time is not the limit there; identifiability is.
- Nothing above N = 1e6 was timed, and no cell reached an hour: the upper wall is not located.
- Memory does not bind below N = 1e7 on this machine.

## 7. This machine only

One CPU (see header), Windows 11, MSVC build without `-march=native`. Bootstrap times depend on the core count, and every time depends on background load. Single-run cells carry no spread. Memory used the Windows working-set counter; the Linux `VmHWM` path is implemented but was not run here.
